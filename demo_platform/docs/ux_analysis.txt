FactoryLens UI/UX 분석 — 제조업체 제안용 실제 관측 데이터 재생 데모
작성일: 2026-10-14

1. 목적과 사용자
공장 운영 담당자가 현재 설비 상태, 이상 후보, 향후 전력량과 프로젝트 기준 비용·탄소를 한 화면에서 이해하고 원본 신호까지 추적할 수 있도록 한다. 실제 공장에 설치된 서비스처럼 보이되, 화면 상단의 '원본 실측 데이터 재생' 표시와 기록 시각·수신 시각을 지속 노출하여 과거 데이터 재생임을 명확히 한다.

2. 프로젝트 가이드와 사용자 요구의 연결
필수: 전력량 예측과 요금·탄소 예측 그래프, MAE 평가, 이상 그래프와 알림, 프로젝트명·팀 소개. 권장: 날짜와 모듈 필터, 예측 이상 경고, 요약 리포트. 가이드의 Streamlit 예시는 구현 방식의 참고이며 이번 사용자 요구인 React 실시간 대시보드로 구현한다. 화면은 운영현황, 설비분석, 예측·비용, 고장진단, 주간리포트의 다섯 메뉴로 구성한다. 모든 페이지 하단에 데이터 검색 채팅을 둔다.

3. 정보 구조와 주요 흐름
운영현황: 전체 모듈의 활성 상태, 선택 관측 시각의 전력·전압·전류·역률·무효전력, 최근 재생 그래프, 수집 로그, 처리하지 않은 이상 후보를 보여준다. 재생·정지, 속도, 날짜 범위, 모듈 선택, 이상 사례 이동은 상단 공통 제어부에 둔다.
설비분석: 13개 관측 모듈을 선택하고 전압·전류·유효전력·역률·지상무효전력을 바꾸어 실제 센서 신호를 확인한다. 상별 값은 범례로 구분하며 단위는 서버의 검증 상태를 함께 표시한다. 모듈 태그를 확정된 물리 설비 수로 해석하지 않는다.
예측·비용: 모델별 예측 곡선, 관측 정답이 있는 구간의 MAE·R², 예측 구간 및 원점, 비용·탄소 계산 기준을 제공한다. R²가 음수인 결과와 검증 구간의 제한을 숨기지 않는다. 프로젝트 계수 180원/kWh, 0.424kgCO₂/kWh는 실제 계약 요금·최신 배출계수가 아님을 명시한다.
고장진단: 규칙·학습 모델·재구성 모델의 점수와 판단 근거를 비교한다. 라벨이 없으므로 '이상 후보'로 표현하고 확정 고장 확률이라는 표현을 사용하지 않는다. 알림 확인은 후보의 처리 상태를 바꾸며 원본 데이터나 진단 결과를 수정하지 않는다. Slack 설정은 별도 서랍에서 서버 연결 상태, 채널과 알림 옵션을 관리한다.
주간리포트: 기간·모듈을 선택해 서버에 GPT-5 mini 생성 요청을 전송하고 실제 생성 상태·오류·근거 데이터를 표시한다. 자동 생성 일정은 시간대·요일·시각과 활성 상태를 명확히 표시한다. 키는 서버에만 보관하며 브라우저에 노출하지 않는다. 키가 실제로 제공되었는지는 서버 설정 상태로 확인하고 가이드에 GPT 키가 있다고 단정하지 않는다.

4. 실시간 재생과 시간의 의미
SSE로 전달받은 실제 관측 행만 그래프와 수집 로그에 추가한다. 기록 시각은 CSV localtime의 명시적인 YYYYMMDDhhmmss 해석을 사용하고, 수신 시각은 현재 서버 또는 브라우저의 실제 수신 시각을 별도로 표시한다. 원본 Unix timestamp에는 기록 시계와의 충돌이 있어 임의 보정하지 않는다. 5초 원본 간격과 재생 배속은 구분해서 표시한다. 정지·다시 연결 중·연결 실패 상태에서 그래프를 가짜 값으로 채우지 않는다. 날짜 또는 사례 이동은 서버의 재생 제어 응답 후 갱신한다.

5. 데이터 신뢰성과 빈 상태
원본 실측 데이터, 예측 값, 이상 후보를 배지와 범례로 구분한다. 원본은 13개 모듈 태그, 5초 센서 관측이며 19개 원본 열을 가진다. 완전 시간 집계와 5초 관측을 섞어 표시하지 않는다. 원본 4월30일 00시 끝점은 완전한 한 시간이 아니다. 서버 응답이 아직 없으면 로딩·미연결·사용 가능한 데이터 없음으로 표시하고 샘플 값을 생성하지 않는다. Slack 미설정, GPT 키 미설정, 요청 실패도 실제 상태 그대로 표시한다. 오류 메시지는 사용자가 재시도할 수 있는 동작을 제공하고 진단용 비밀 정보는 숨긴다.

6. 시각 언어와 접근성
브랜드는 FactoryLens, 제품 부제는 '제조업체 데모라인'으로 한다. Navy 사이드바, 밝은 ivory 본문, teal 실측 그래프, coral/red 이상 강조를 사용한다. 장식용 공장 이미지 대신 실제 데이터 차트·수치·로그를 중심에 둔다. 숫자는 자리수와 단위를 함께 표시하고 시각 표기를 일관되게 유지한다. 버튼·선택·서랍은 키보드로 접근 가능하고 포커스가 보인다. 상태는 색상 외에 텍스트·아이콘으로 전달한다. 작은 화면에서는 메뉴를 축소하고 카드·차트를 세로로 배치한다.

7. API와 프런트엔드 경계
API 어댑터에 메타데이터, 재생 상태/제어, SSE, 센서 조회, 예측/평가, 진단/알림 확인, Slack 설정, 주간리포트/일정, 데이터 검색을 모은다. 백엔드 계약이 확정되면 어댑터에서 응답 구조를 정규화하며 화면에는 원본 응답의 근거와 상태만 전달한다. 인증키·Webhook 비밀 값은 화면·저장소·프런트엔드 번들에 저장하지 않는다. 외부 배포·업로드는 수행하지 않고 localhost 통합 데모로 검증한다.

8. 완료 검증
React/Vite 프로덕션 빌드, 실제 백엔드 연결, SSE 수신과 재생 제어, 날짜·모듈·센서 필터, 모든 페이지 하단 데이터 검색, 진단 후보 확인, Slack 미설정 상태, GPT 요청·오류 상태, 보고서 일정 저장을 검증한다. 데스크톱과 좁은 화면에서 텍스트·차트·서랍이 잘리지 않는지 브라우저 시각 검토를 수행한다. 실제 외부 Slack 전송이나 예약 실행은 사용자/상위 작업의 명시된 범위 안에서만 처리한다.
