P1UX01 · 설비분석 → 하단 검색 / 고장 검토 → 리포트

화면에서 검토한 대상과 후속 작업의 범위를 명확히 연결

확인한 내용
과거 조회의 start/end는 SearchChat에 전달되지만 api.search는 실제 요청 context에 module_id와 cursor_time만 보낸다. 후보 구간 반복 재생도 전역 모듈·시각과 독립적이며, 리포트는 전역 선택 범위로 생성한다. 실제 화면에서는6호기·12월1일의 생성 조건 아래에 전체 모듈·3월6~13일의 저장 보고서가 표시됐다. 저장 보고서 자체의 대상·기간 배지는 정확했다.
사용자에게 생길 수 있는 문제
사용자가 '지금 보고 있는 설비·기간'을 검색하거나 보고서로 만드는 것으로 오해할 수 있다. 혼동의 발생률은 사용자 실험으로 확인하지 않았다.
개선안
검색·리포트 실행부에 대상 모듈, 실제 관측 기간, 원본/합성, 검색 기준을 칩으로 표시한다. 적용 조회 범위를 검색 API의 검증된 범위로 전달하거나 현재 재생 기준임을 명시한다. 후보를 보고서로 연결하는 동작은 별도의 신규 기능으로 설계한다. 현재 조건으로 새로 생성하는 영역과 과거 저장본 열람을 제목 수준에서 분리한다.
완료 판단 기준
과거 조회와 검색 요청의 실제 범위가 일치하거나 기준 전환을 명시한다. 후보 보고서 생성 전 대상·기간이 표시되며 묵시적으로 전역 범위가 바뀌지 않는다.
근거 유형: 구현과 화면 관찰 + 혼동 가능성에 대한 설계 가설
작업 범위: 중간 · 검색 API와 화면 계약 검토 필요

확인한 내용
공통 후보 구간에서는 다섯 센서 모두 붉은 선과 점으로 표시된다. 3상 선도 후보 구간에서는 같은 붉은 표현을 사용한다. 규칙·AE·IF 점수는 별도 그래프에서 제공된다.

P1UX04 · 알림 센터 · 저장 알림 이력

읽음·담당자 확인·실제 고장 여부의 언어 정리

확인한 내용
읽음 처리는 알림 센터에, ACK는 저장 알림 표의 '확인/확인됨'에 존재한다. 실제 고장은 미검증이라고 별도 안내한다.
사용자에게 생길 수 있는 문제
'확인됨'이 알림을 읽었다는 뜻인지, 점검 완료인지, 고장이 확정되었다는 뜻인지 해석이 갈릴 수 있다.
개선안
현재 기능은 '읽음', '담당자 확인(ACK)', '실제 고장 여부 미검증'으로 분리 표기한다. 담당자 지정·검토 메모·조치 완료는 추가 데이터가 필요한 후속 기능으로 설계한다.
완료 판단 기준
ACK 버튼을 눌렀을 때 무엇이 바뀌는지 설명하고, ACK만으로 고장 확정·해결 완료 배지가 생성되지 않는다.

P1UX05 · 센서·진단 점수 차트 범례

작은 범례 문자의 대비 보완

확인한 내용
S상과 IF 점수에 사용하는 #0284c7을 흰색 위 문자로 표시하면 계산 대비는 약4.095:1이다. 설치된 Recharts 범례는 선 색을 문자에 적용한다. 센서 범례는11px, 일부 점수 차트 축·범례는10px다.
사용자에게 생길 수 있는 문제
차트 해석에 필요한 작은 글자를 읽기 어렵다. 일반 문자 대비 4.5:1 기준에 미치지 않는 색 조합이 존재한다. 전체 사이트의 접근성 적합 여부를 평가한 것은 아니다.
개선안
범례 문자를 진한 중립색으로 고정하고 선·아이콘에서 채널 색을 유지한다. 핵심 측정값은14px 안팎, 축·범례는12px 안팎을 설계 목표로 시험한다. 이 글자 크기는 표준의 의무 수치가 아니다.
완료 판단 기준
