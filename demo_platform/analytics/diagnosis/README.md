# 전력 신호 이상 후보 탐지

이 디렉터리는 원본 5초 센서에 대한 여섯 형태의 조건 검사, Isolation Forest, Autoencoder, 합성 형태 분류기를 포함한다. 실제 고장 종류·시각 정답은 제공되지 않았다. 경보와 합성 형태 유사도는 확정 고장 진단 또는 실제 고장 확률이 아니다.

## 실행과 API

```python
import sys
sys.dont_write_bytecode = True
sys.path.insert(0, r'E:\AI work\AWS_프로젝트\demo_platform\analytics\diagnosis')
from detector import Detector
detector = Detector()
answer = detector.diagnose_batch(rows)  # 원본 필드의 dict 목록
```

`diagnose_batch(rows)` 모듈 함수도 제공한다. 모델은 첫 호출 때 한 번만 불러온다. `localtime`은 14자리 `YYYYMMDDHHMMSS`이며, 대체 `time`은 시간대 없는 ISO 시각이다. `module(equipment)` 또는 `module_id`와 14개 필수 센서가 필요하다. 잘못된 시각, 모듈, 결측·비유한 센서는 오류로 반환하며 0으로 대체하지 않는다. 입력 행은 수정하지 않는다. 원본 Unix `timestamp`는 알려진 오프셋 전환 문제 때문에 계산에 사용하지 않는다.

각 반환 행에는 `rules`, `ai`, `status`, `confidence`, `source_kind`, `source_tag`, `model_available_from`, `evaluation_scope`가 있다. 원본 재생은 `source_kind=recorded`; 별도 합성 체험은 호출 행에 `source_kind=synthetic`와 시나리오 `source_tag`를 반드시 넣는다. `confidence.fault_probability`는 항상 null이다. `ai.class_probs`는 일곱 합성 변환 클래스와의 유사도이며, `unmodified_reference`도 검증된 정상 상태를 뜻하지 않는다.

## 기간과 데이터 범위

- 기준선·모델 학습: `[2024-12-01 00:00, 2025-01-01 00:00)`.
- 임계값 보정, AE epoch 선택, 분류기 선택: `[2025-01-01 00:00, 2025-02-01 00:00)`.
- 보정 이후 독립 표본 비교: `[2025-02-01 00:00, 2025-04-30 00:00)`.
- 원본 전수검사: 12월 1일부터 4월 30일 00시 끝점까지 33,696,013행 모두. 따라서 12월·1월 원본 후보 조회는 학습·보정 기간의 사후 조회이며, 보정 이후 성능 평가와 구분한다.

학습·보정에는 기존 시간층화 원본 표본 187,200행을 읽기 전용으로 사용했다. 13모듈×3,600시간에 시간별 4행씩이며, 새 분할의 행 수는 38,688 / 38,688 / 109,824이다. 시간층화 표본의 최초·최후 시각은 위 기간 경계와 다를 수 있다.

여섯 조건 검사와 AE는 원본 모든 행을 처리했다. IF와 분류기는 187,200행 표본 및 최종 180개 후보의 정확한 원본 최대점에서 계산했다. 모든 원본 행에서 IF·분류기를 실행했다고 해석하면 안 된다. 원본 크기·mtime·SHA256과 저장 모델 SHA256의 보존을 검증했다.

## 여섯 조건 검사

12월 모듈별 median과 MAD/IQR로 신호를 표준화하고, 각 모듈·시간대 기준선도 별도로 학습한다. 경계값은 1월 원본 점수의 모듈별 99.9백분위수다. 야간은 22–06시 표본만으로 경계를 정한다. 정확한 수식은 `detector.py:rule_scores`, 경계값은 `thresholds.json`에 저장한다.

| 형태 | 실제 검사 근거 |
|---|---|
| 부하 불균형 | 특정 상 전류 증가와 모듈 평소 대비 전류 불균형 증가 |
| 무효전력 급증 | Q 증가, Q/P 증가와 역률 저하 보조 신호 |
| 역률 급감 | 상별 최소·평균 역률 저하와 Q/P 증가 보조 신호 |
| 비정상 패턴 | 원 센서의 큰 강건 편차 또는 보정된 P/ΣVIPF 비율 편차; AE 경보도 이 유형 후보로 보관 |
| 야간 이상가동 | 야간의 모듈·시간대 평소 대비 전력·전류 초과; 야간이라는 사실이나 operation=1만으로 경보하지 않음 |
| 전류만 증가 | 평균 전류 증가와 전력/전류 관계의 불일치; 전력 자체의 큰 편차는 감점 |

P/ΣVIPF 계수는 12월 모듈별 경험적 중앙값으로 보정한다. 원본 전력·무효전력 단위와 계측 범위가 불확실하므로 이 계수를 인증된 단위 환산이나 이상적인 삼상 전력식으로 해석하지 않는다. 원본 전류 불균형 배경이 넓고, 학습·보정 기간에 미확인 이상이 포함될 수 있어 일부 경계가 보수적일 수 있다.

## AI 및 검증 결과의 의미

AE는 24→32→12→32→24 구조이며 1월 검증 손실로 조기 종료했다. 99 epoch 실행 중 79 epoch를 선택했다. IF는 192개 트리, 최대 표본 1,024개를 사용한다. RF와 XGB의 일곱 클래스 비교는 12월 학습 기반, 1월 검증 기반, 2–4월 별도 시험 기반에 여섯 변환을 삽입한 합성 실험이다. 한 원본 기반 행이 일곱 클래스에 반복되므로 시험 14,000행은 독립 기반 행 14,000개가 아니다.

XGB는 합성 검증 macro F1 0.979660으로 선택했고, 합성 시험 macro F1은 0.979432이다. 합성 이진 이상 시험의 재현율은 조건 검사 0.9495, AE 0.714917, IF 0.035667이다. 고정된 경계에서 IF가 보수적이라는 한계도 유지한다. 이 수치들은 실제 고장 정확도가 아니다. 원본 무정답 표본의 경보 비율도 거짓 양성률로 해석할 수 없다.

## 원본 후보와 재생

원본 연속 경보를 같은 모듈·유형의 인접한 5초 시점으로 묶었다. 3개 연속 시점은 15초 분량의 관측이지만 시작–끝 시각 차이는 10초다. 단일 시점도 플랫폼 경고로 기록될 수 있으며, 연속 여부와 무관하게 모든 실제 후보는 `unconfirmed_candidate`다.

| 원본 이벤트 ID | 모듈 | 원본 구간 | 설명 |
|---|---:|---|---|
| abnormal_pattern_0093 | 17 | 2025-03-13 19:45:05–19:45:15 | AE 초과; 기본 재생 19:43–19:55 |
| abnormal_pattern_0091 | 15 | 2025-02-28 04:38:20–04:38:30 | AE와 IF 초과; 재생 04:36–04:42 |
| abnormal_pattern_0092 | 17 | 2025-02-19 03:04:00–03:04:10 | AE 초과; 재생 03:02–03:08 |
| power_factor_drop_0061 | 5 | 2025-02-26 06:47:00–06:47:10 | 약한 조건 후보; AE·IF 미초과, 합성 reference 유사도 높음 |

부하 불균형·무효전력 급증·야간 이상가동·전류만 증가에는 3시점 이상 연속 후보가 없었다. 이를 실제 유형이 없다는 증명이나 여섯 고장을 찾았다는 주장으로 바꾸지 않는다. 부족한 형태를 체험할 때는 사용자가 선택하는 별도 합성 시나리오로 표시한다.

`candidates.json`의 화면용 `score`는 초과 배수이며 `threshold=1`이다. 비정상 패턴은 조건 점수/해당 경계와 AE 점수/AE 경계의 최댓값이고, 다른 유형은 조건 점수/해당 경계다. 원 조건 점수와 모델 점수는 `archive_rule_equivalent_score`, `rules_at_peak`, `ai`에 보존한다. API의 `rules[].score`는 원 조건 점수이므로 해당 `rules[].threshold`와 함께 표시한다. 저장 모델 경계값은 후보 표시 정규화 과정에서 바꾸지 않았다.

`all_rule_events.csv.gz`는 모든 희소 후보 구간, `candidates.json/csv`는 유형당 최대 30개의 검토용 후보이다. 후보 180개가 정답 고장 180개를 뜻하지 않는다. 원본 밀집 구간은 플랫폼 원본 인덱스에서 읽으며 이 디렉터리에 원본 데이터 사본을 만들지 않았다.

## 저장 결과와 재현 확인

`train_system.py` → `scan_original.py` → `verify_system.py`가 학습·전수검사·검증 코드다. 이미 실행된 모델은 `models.joblib`, `ae.pt`, `synthetic_xgb.json`에 저장되어 있다. `results.json`은 품질 지표, `scan_summary.json`은 전수 범위, `verification.json`은 검증 결과다. `integration_metadata.json`에는 모델 카드, 명시적 기간 경계, 재생 이벤트를 정리했다.

검증 통과: 저장 모델 200행 재로드 일치, 후보 180개 최대점 재생 오차 0, Unix key 변경에도 점수 불변, 입력 불변, 합성 태그 보존, 잘못된 입력 거부, 후보 5초 간격·원본 SHA·크기·mtime·모델 SHA 보존. 실제 고장 정답이 없는 점은 검증 통과로 해소되지 않는다.
